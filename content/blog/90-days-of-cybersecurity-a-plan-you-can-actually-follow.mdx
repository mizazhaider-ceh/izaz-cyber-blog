Most roadmaps are link lists. This one is a workout program: networking before hacking, Linux before Python, web fundamentals before Burp, and a real vulnerable lab, not screenshots of one, when it is time to attack. Follow it in order and you will finish with skills you can demonstrate, not just videos you watched.

That is the idea behind 90 Days of Cyber, a 90-day hands-on study plan that takes you from zero to job-ready fundamentals. One to two hours a day, every tool free, every single day ends with something you built, broke, or captured yourself.

<Callout type="NOTE" title="About this article">
This article is a study plan, not a run log. It lays out the 90 Days of Cyber plan from its public repository and explains the order and the rules. It does not claim a completed 90-day run. The one command sample below is a real command from the plan, and its output is labelled illustrative.
</Callout>

## The 10 phases

| Days | Phase | What you will be able to do |
|------|-------|------------------------------|
| 1-7 | Networking Fundamentals | Read a network like a map, capture traffic with [Wireshark](https://www.wireshark.org/docs/), scan with [nmap](https://nmap.org/docs.html) |
| 8-14 | Security Foundations | Think in CIA triad terms, hash and crack, spot phishing on sight |
| 15-28 | Linux Command Line | Live in the terminal, script in bash, clear Bandit levels |
| 29-42 | Python for Security | Write your own tools, parse logs, build a port scanner |
| 43-56 | Web Hacking with the PenTrix VulnLab | Intercept traffic with [Burp Suite](https://portswigger.net/burp), exploit real vulnerabilities, earn 50 flags |
| 57-63 | Git and GitHub | Version everything, publish your work, collaborate with pull requests |
| 64-70 | SIEM and Blue Team Basics | Hunt threats in logs with the [Elastic Stack](https://www.elastic.co/guide/en/elasticsearch/reference/current/index.html), write an incident note |
| 71-77 | Cloud Security Basics | Secure AWS and Azure resources the way attackers see them |
| 78-84 | Review and Guided Practice | Solve TryHackMe, HackTheBox, and picoCTF challenges against the clock |
| 85-90 | Capstone: Prove Your Skills | Finish kill-chain scenarios, ship a project, write a professional writeup |

After day 90 comes the career track, days 91 to 95: a one-page resume, a clean GitHub, and a real job search plan.

## The rules of the plan

Budget 1 to 2 hours a day. Every day is scoped for that. Some days will take less, a few will take more, and that is fine.

Go in order. Each phase assumes the one before it. You cannot enjoy web hacking in phase 5 if you skipped the Linux terminal in phase 3. That order is the whole point: packets are the alphabet of everything in security, so the plan starts with networking, and the hacking comes only after the foundations can carry it.

Everything is free. Every tool, platform tier, and resource in the plan has a free option. If something asks for a card, there is a free tier or a free alternative named in the day's task. The cloud phase warns you before anything could cost money and ends with a cleanup day so the free tier stays free.

Track your progress. Each day ends with a checkbox. Check it only when the hands-on task is actually done. Fork the repo and check them off in your own copy, or print the progress list and pin it to your wall.

Build in public. From phase 6 onward you push your scripts, notes, and writeups to GitHub. Employers hire people who can show their work.

## The labs are the plan, not an appendix

Reading about vulnerabilities does not teach exploitation. The labs are woven into the daily tasks, not parked in an appendix.

The plan's home lab for web hacking is the [PenTrix VulnLab](/blog/pentrix-vulnlab-building-a-deliberately-vulnerable-lab), an intentionally vulnerable web app with 201 challenges across 29 modules, each its own small website, running locally with docker compose. Flags are earned only by genuine exploitation. You meet it daily in phases 5 and 10, and the phase 5 milestone is 50 earned flags plus a written writeup of your favorite exploit. For an example of what a finished writeup looks like, see the [CTF investigation writeup](/blog/documenting-a-ctf-investigation-cscb-2026).

Other labs in the plan: [TryHackMe](https://tryhackme.com/) guided rooms with a free tier, [HackTheBox](https://www.hackthebox.com/) Starting Point machines with a free tier, [picoCTF](https://picoctf.org/) free challenges for timed practice, and [OverTheWire Bandit](https://overthewire.org/wargames/bandit/), a Linux wargame over SSH, at the end of phase 3. For the scanning skills in phase 1, the [network reconnaissance automation guide](/blog/building-network-reconnaissance-automation) covers the same workflow in depth.

A command from phase 1, the first scan you run in the plan:

```bash
nmap -sn 192.168.56.0/24
```

Illustrative output:

```text
Nmap scan report for 192.168.56.10
Host is up.
Nmap scan report for 192.168.56.20
Host is up.
```

## What if you fall behind

The days are numbered, not dated. Miss a week, pick up where you left off. Phase 9 exists specifically to repair weak spots: a review of your weakest days, and timed redos of labs you already solved.

Can you skip to the hacking part? You can, but you will be slower at it. Phases 1 through 4 are what make phase 5 fun instead of frustrating.

Either Windows or Mac works for the early phases. In phase 3 you [install a Linux VM](/blog/building-a-practical-linux-security-lab), and from then on most hands-on work happens in Linux.

## What the plan does not promise

It gives you demonstrable fundamentals: a GitHub with real projects, labs you can talk through, and the vocabulary to survive a junior interview. Days 91 to 95 turn that into applications. No plan replaces persistence, but this one replaces wondering what to learn next.

Everything here targets your own machines, your own cloud accounts, or platforms built for practice. Never test systems you do not own or have written permission to test.
